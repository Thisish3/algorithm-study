# 스택 · 큐 (그리고 덱)

## 한 줄 요약

- **스택**: 마지막에 넣은 것을 먼저 꺼낸다(LIFO). "가장 최근의 아직 안 끝난 것"이 필요할 때.
- **큐**: 먼저 넣은 것을 먼저 꺼낸다(FIFO). "도착 순서대로" 처리하거나, 오래된 것부터 버릴 때.
- **덱(deque)**: 양쪽 끝에서 넣고 뺄 수 있다. 큐와 스택을 다 한다.

## 왜 쓰나: 두 예제

**큐 — 슬라이딩 윈도우 요청 한도** (`rate_limiter`): "최근 W초 동안 최대 L건". 통과한 요청 시각을
큐에 넣고, 새 요청이 오면 창 밖으로 나간 시각을 **앞에서** 버린다. 시각은 오름차순으로 들어오니
오래된 것이 항상 앞에 있다. 남은 개수가 L보다 작으면 통과. API 게이트웨이의 요청 한도와 같은 구조다
(토큰 한도면 개수 대신 토큰 합을 들고 다닌다).

**스택 — 단조 스택** (`next_slower`): 각 요청 뒤로 처음 나오는 "더 느린 요청"까지의 거리. 모든 쌍을
보면 O(n²). 스택에 "아직 더 큰 값을 못 만난 것들"을 쌓아 두면, 새 값이 올 때 그보다 작은 것들이
한꺼번에 답을 얻고 빠진다. 스택 안은 항상 내림차순이라 **단조 스택**이라 부른다.

## 틀 (외워 둘 것)

```python
stack = []; stack.append(x); stack.pop(); stack[-1]      # 스택
from collections import deque
q = deque(); q.append(x); q.popleft(); q[0]               # 큐

# 단조 스택: 다음으로 큰 원소
for i, x in enumerate(a):
    while stack and a[stack[-1]] < x:
        j = stack.pop(); ans[j] = i - j      # 또는 a[i]
    stack.append(i)

# 슬라이딩 윈도우: 창 밖으로 나간 것을 앞에서 제거
while q and q[0] <= t - window: q.popleft()
```

```cpp
std::vector<int> st; st.push_back(x); st.pop_back(); st.back();
std::deque<int> q; q.push_back(x); q.pop_front(); q.front();
// std::stack, std::queue도 있지만 vector/deque가 더 자유롭다
```

괄호 짝 맞추기(스택 기본형):

```python
pair = {')': '(', ']': '[', '}': '{'}
```

## 자주 하는 실수

- **파이썬 `list.pop(0)`을 큐로 쓰기**: O(n). `deque.popleft()`를 쓴다.
- **빈 스택에서 pop/top**: 꺼내기 전에 비었는지 먼저 본다. 괄호 문제에서 닫는 괄호가 먼저 나오는 경우.
- **단조 스택에 값 대신 인덱스를 넣기 / 반대로**: 거리를 구하려면 인덱스, 값만 필요하면 값. 보통 인덱스를 넣고 값은 배열에서 본다.
- **같은 값 처리 (`<` vs `<=`)**: "더 큰"인지 "크거나 같은"인지에 따라 등호가 바뀐다.
- **창 경계**: "최근 W초"가 `t - W`를 포함하는지 문제에서 확인한다. 예제는 `<= t - W`를 버린다(W초 전 요청은 창 밖).
- **거절된 요청을 한도에 세기**: 예제는 통과한 요청만 센다. 문제마다 다르다.

## 복잡도

단조 스택과 슬라이딩 윈도우 모두 **각 원소가 한 번 들어가고 한 번 나가므로** 전체 O(n).
안쪽 while이 있어도 O(n²)이 아니다(분할 상환, amortized).

## 서빙 시스템과의 연결

- 게이트웨이 요청·토큰 한도: 슬라이딩 윈도우 큐 (예제). 고정 창(분 단위로 끊기)보다 경계에서 몰리는 요청에 공정하다.
- 엔진의 대기열: 기본은 큐(FIFO). 우선순위가 들어가면 힙(04).
- 링 버퍼: 크기가 고정된 큐를 배열 하나로 (머리·꼬리 인덱스를 나머지 연산으로 돌림). 로그·이벤트 버퍼, 생산자-소비자 큐.
