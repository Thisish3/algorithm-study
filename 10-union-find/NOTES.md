# 유니온 파인드 (서로소 집합, DSU)

## 한 줄 요약

"이 둘이 같은 묶음인가?"와 "두 묶음을 합쳐라"를 거의 O(1)에 처리한다. 묶음이 **합쳐지기만 하고 나뉘지 않을 때** 쓴다.

## 어떻게 동작하나

묶음마다 대표 하나를 두고, 각 원소는 부모를 가리킨다. 부모를 따라 올라가 닿는 대표가 같으면 같은 묶음이다.
두 가지 요령으로 트리를 낮게 유지한다.

- **경로 압축**: `find`하며 지나온 원소를 대표에 바로 붙인다. 다음 `find`가 한 번에 끝난다.
- **크기(또는 높이) 기준 합치기**: 작은 묶음을 큰 묶음 밑에 붙인다.

둘을 같이 쓰면 연산 하나가 사실상 상수 시간이다(역 아커만 함수, 현실에서 4 이하).

## 두 예제

**연결 질의** (`chip_groups`): 칩 사이에 링크가 하나씩 추가될 때 "a와 b가 이어져 있나", "a의 묶음 크기는".
매번 BFS(02번)로 확인하면 질의마다 O(N+M)이다.

**크루스칼 최소 신장 트리** (`cheapest_links`): 서버를 모두 잇는 가장 싼 링크 집합. 싼 링크부터 보고,
이미 같은 묶음인 두 서버를 잇는 링크는 고리를 만드므로 건너뛴다. 예제 입력의 답은 11.

둘 다 무작위 입력 300개로 확인했다. 질의는 단순 반복으로 구한 묶음과, 최소 신장 트리는 링크의 모든
부분집합을 본 정답과 비교했다.

## 틀 (외워 둘 것)

```python
parent = list(range(n + 1)); size = [1] * (n + 1)

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]   # 경로 절반 압축 (재귀 없이)
        x = parent[x]
    return x

def union(a, b):
    a, b = find(a), find(b)
    if a == b: return False
    if size[a] < size[b]: a, b = b, a
    parent[b] = a; size[a] += size[b]
    return True
```

크루스칼:

```python
for cost, u, v in sorted(edges):    # 비용이 튜플 맨 앞
    if union(u, v): total += cost; used += 1
ok = used == n - 1                  # 다 이어졌는지
```

## 자주 하는 실수

- **대표끼리 합치지 않기**: `parent[b] = a`를 `find` 없이 원소에 바로 하면 묶음이 깨진다.
- **파이썬 재귀 `find`**: 경로 압축 전에 깊어지면 재귀 한도에 걸린다. 반복문으로.
- **크기를 대표가 아닌 원소에서 읽기**: `size[find(a)]`.
- **크루스칼에서 다 이어졌는지 확인 안 하기**: 그래프가 끊겨 있으면 `n - 1`개를 못 고른다.
- **나누기가 필요한 문제에 쓰기**: 링크가 끊기는 문제는 유니온 파인드로 바로 안 된다(거꾸로 시간을 돌려 "추가"로 바꾸는 요령이 있다).
- **1번부터 쓰는데 크기 n으로 만들기**: `n + 1`.

## 복잡도

연산당 거의 O(1) (역 아커만). 크루스칼은 정렬 O(M log M)이 지배.

## 서빙 시스템과의 연결

- **칩 묶음 파악**: 서버 안 칩들이 링크로 어떻게 이어져 있는지 묶음과 크기를 빠르게 (예제 1). 하이퍼엑셀처럼 링을 4장 링 2개로 나눠 쓰면 어떤 카드가 같은 링에 있는지가 곧 이 질의다.
- **네트워크 설계**: 모든 서버를 가장 싸게 잇는 링크 (예제 2).
- **같은 대화 묶기**: 요청 ID들이 "같은 세션" 관계로 이어질 때, 로그에서 세션 단위로 묶어 집계.
- **장애 영향 범위**: 이어진 묶음 단위로 영향을 계산.
