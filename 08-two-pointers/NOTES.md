# 투 포인터

## 한 줄 요약

인덱스 두 개를 **각각 한 방향으로만** 움직여, 이중 반복 O(n²)을 O(n)으로 줄인다. 두 가지 모양이 있다:
같은 방향으로 가는 **슬라이딩 윈도우**, 양 끝에서 안으로 좁히는 **양 끝 포인터**.

## 왜 쓰나: 두 예제

**슬라이딩 윈도우** (`token_window`): 들어온 순서대로의 요청 토큰 수에서, 스텝 예산 B 안에 넣을 수 있는
연속 요청의 최대 개수. 토큰 수가 0 이상이라 오른쪽을 넓히면 합이 늘고, 왼쪽을 줄이면 합이 준다. 그래서
예산을 넘을 때만 왼쪽을 당기면 된다. 왼쪽은 절대 뒤로 가지 않으니 두 포인터가 합쳐 2n번만 움직인다.
엔진이 한 스텝에 토큰 예산만큼 요청을 묶는 것(⑥ 연속 배칭·chunked prefill)과 같은 발상이다.

**양 끝 포인터** (`pair_slots`): 슬롯 하나에 요청 최대 2개, 토큰 합 C 이하. 슬롯 수 최소. 정렬 후 가장 큰
요청은 어차피 슬롯 하나를 쓴다. 그 슬롯에 가장 작은 요청을 같이 넣어 보고, 안 되면 혼자 보낸다.
가장 작은 것과도 안 맞으면 누구와도 안 맞기 때문에 이 선택이 손해가 없다.

예제 둘 다 무작위 입력(400개, 300개)으로 모든 경우를 본 정답과 비교해 맞는 것을 확인했다.

## 틀 (외워 둘 것)

```python
# 슬라이딩 윈도우: 조건을 깨면 왼쪽을 당긴다
left = total = 0
for right, x in enumerate(a):
    total += x
    while total > limit:          # 조건이 깨진 동안
        total -= a[left]; left += 1
    best = max(best, right - left + 1)

# 양 끝 포인터: 정렬 후 안으로 좁힌다
a.sort(); lo, hi = 0, len(a) - 1
while lo < hi:                    # (짝짓기는 lo <= hi로 혼자 남은 것도 센다)
    s = a[lo] + a[hi]
    if s == target: ...; lo += 1; hi -= 1
    elif s < target: lo += 1      # 합을 키우려면 작은 쪽을 올린다
    else: hi -= 1                 # 합을 줄이려면 큰 쪽을 내린다
```

## 언제 되고 언제 안 되나

- 슬라이딩 윈도우는 **원소가 음수가 아닐 때**(넓히면 합이 늘기만 할 때) 된다. 음수가 섞이면 06번 해시의 누적합+해시로 간다.
- 양 끝 포인터는 **정렬해도 답이 바뀌지 않는 문제**에서 쓴다(쌍의 합, 짝짓기). 원래 순서가 중요하면 못 쓴다.

## 자주 하는 실수

- **음수가 있는데 슬라이딩 윈도우**: 왼쪽을 당겨도 합이 늘 수 있어 틀린다.
- **`while` 대신 `if`로 왼쪽을 한 번만 당기기**: 여러 칸을 줄여야 할 때 틀린다.
- **창 길이 계산**: `right - left + 1`.
- **양 끝 포인터에서 정렬을 잊기**.
- **짝짓기 종료 조건**: 마지막에 혼자 남은 원소(`lo == hi`)도 슬롯이 필요하다. 예제는 `lo <= hi`.
- **같은 값이 여러 개일 때 쌍 개수 세기**: 같은 값 묶음을 한 번에 건너뛰어야 중복 없이 센다.

## 복잡도

두 포인터가 각각 최대 n번 움직이므로 O(n). 정렬이 필요하면 O(n log n).

## 서빙 시스템과의 연결

- 스텝 토큰 예산 안에서 요청 묶기 (예제 1, 연속 배칭).
- 슬롯·GPU에 요청을 짝지어 담기 (예제 2, 빈 패킹의 쉬운 경우).
- 시간 창 지표: "최근 N초 동안의 요청 수·토큰 수"를 창을 밀며 갱신 (05번 큐와 같은 모양).
- 정렬된 두 기록 합치기(merge): 두 서버의 시간순 로그를 한 줄로.
