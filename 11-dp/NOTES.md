# DP (동적 계획법)

## 한 줄 요약

큰 문제의 답을 **작은 문제의 답으로** 만들 수 있고, 같은 작은 문제가 여러 번 나올 때, 작은 답을 표에 적어
두고 다시 쓴다. 모든 경우를 다 보면 지수 시간인 문제를 다항 시간으로 바꾼다.

## DP 문제를 푸는 순서 (이 순서대로 적는다)

1. **상태**: `dp[...]`가 무엇을 뜻하는지 한 문장으로. 예: "블록 b개까지 썼을 때의 최대 점수".
2. **점화식**: 마지막 선택 하나를 기준으로 나눈다. "이 요청을 넣느냐 마느냐", "마지막 토큰을 어떻게 맞추느냐".
3. **초기값**: 가장 작은 경우. 빈 배낭 0, 빈 문자열과의 거리는 길이.
4. **계산 순서**: 점화식이 참조하는 칸이 먼저 채워지게.
5. **답의 위치**: `dp[B]`, `dp[n][m]` 등.

## 두 예제

**0/1 배낭** (`admit_knapsack`): 대기 요청마다 필요한 KV 블록 수와 우선순위 점수. 블록 B개 안에서 점수 합 최대.
각 요청은 통째로 받거나 말거나. `dp[b] = max(안 넣음 dp[b], 넣음 dp[b - 블록] + 점수)`. 한 줄짜리 표를 쓰고
**b를 큰 쪽부터** 돌아야 같은 요청을 두 번 넣지 않는다. 예제 답 110 (블록 4+6).

**편집 거리** (`output_diff`): GPU와 새 칩이 같은 프롬프트로 만든 출력 토큰 열이 얼마나 다른가. 토큰 하나
넣기·지우기·바꾸기의 최소 횟수. 마지막 토큰끼리 같으면 그대로, 다르면 세 가지 중 가장 싼 것 + 1.
예제: "sat"→"sits", "the"→"a" 두 번. 표 전체 대신 직전 줄만 들고 가서 메모리를 줄인다.

둘 다 무작위 입력 300개로 확인했다. 배낭은 모든 부분집합을, 편집 거리는 재귀 정의를 그대로 계산한 값과 비교했다.

## 틀 (외워 둘 것)

```python
# 0/1 배낭 (한 줄 표, 거꾸로)
dp = [0] * (B + 1)
for w, v in items:
    for b in range(B, w - 1, -1):
        dp[b] = max(dp[b], dp[b - w] + v)

# 무한 배낭(같은 물건 여러 번): 앞에서부터 돈다
for w, v in items:
    for b in range(w, B + 1):
        dp[b] = max(dp[b], dp[b - w] + v)

# 두 열 비교 (편집 거리, LCS): dp[i][j] = 앞 i개와 앞 j개
for i in 1..n:
    for j in 1..m:
        if a[i-1] == b[j-1]: dp[i][j] = dp[i-1][j-1] (+1 for LCS)
        else: dp[i][j] = ...
```

재귀 + 메모로 먼저 맞게 짜고, 필요하면 반복문으로 바꾼다:

```python
from functools import lru_cache
@lru_cache(None)
def f(i, b): ...        # 파이썬은 깊으면 sys.setrecursionlimit
```

## 자주 하는 실수

- **0/1 배낭을 앞에서부터 돌기**: 같은 물건을 여러 번 넣게 된다(무한 배낭이 돼 버림).
- **상태를 말로 정의하지 않고 코드부터 짜기**: 점화식이 흔들린다. 1번 단계를 꼭 적는다.
- **초기값**: 최솟값 문제에서 0으로 시작하면 틀린다(INF로). "불가능"을 따로 표시해야 하는 경우.
- **인덱스 한 칸 밀림**: `dp[i]`가 "앞 i개"인지 "i번째까지"인지 섞인다. 앞 i개로 통일하면 `a[i-1]`.
- **욕심으로 풀리는 줄 알기**: 배낭은 "점수/블록이 높은 것부터" 넣으면 틀린다(쪼갤 수 있을 때만 맞음).
- **파이썬 2차원 표를 `[[0]*m]*n`으로 만들기**: 같은 줄을 공유한다. `[[0]*m for _ in range(n)]`.

## 복잡도

배낭 O(N·B), 편집 거리 O(n·m). 표 크기 × 칸당 계산.

## 서빙 시스템과의 연결

- **요청 받아들이기**: KV 메모리 예산 안에서 어떤 요청을 먼저 받을지 (예제 1). 실제 엔진은 빠른 욕심 규칙을 쓰지만, 최적값과 비교하는 기준으로 쓸 수 있다.
- **출력 비교(차분 테스트)**: 같은 입력에 대한 두 엔진·두 칩의 출력 차이 (예제 2). 하이퍼엑셀처럼 golden과 칩 결과를 비교할 때, 완전 일치가 아닌 "얼마나 다른가"가 필요하면 이 거리.
- **파이프라인 단계 나누기**: 07번은 이분 탐색으로 풀었지만 DP로도 된다(레이어 i까지를 k단계로 나눈 최소 비용).
- **스펙 디코딩 수락 길이 기대값**도 단계별 확률을 누적하는 작은 DP다.
