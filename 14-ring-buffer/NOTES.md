# 링 버퍼 (원형 큐)

## 한 줄 요약

크기가 정해진 배열 하나를 **원처럼** 돌려 쓰는 큐. 끝에 닿으면 처음으로 돌아간다(`% 크기`). 메모리를 새로
잡지 않고 넣기·꺼내기가 O(1)이라 로그 버퍼, 지표 버퍼, 생산자-소비자 큐, 네트워크·장치 큐에 쓰인다.

## 두 예제

**덮어쓰는 기록 버퍼** (`ring_log`): 최근 지연 N개만 보관. 꽉 찼는데 새 값이 오면 가장 오래된 값을 덮어쓴다.
머리(head) 위치와 개수(count)를 들고, 새 값은 `(head + count) % N`에 쓴다. 평균을 O(1)에 주려고 합도
같이 들고 다닌다(빠지는 값은 빼고 들어오는 값은 더한다).
예제: 용량 3에 10, 20을 넣으면 평균 15, 30·40을 넣으면 10이 덮여 평균 30.
검증: 무작위 300개 명령열에서 파이썬 `deque(maxlen=N)` 모델과 매 연산을 비교했고, Python과 C++ 출력도 같았다.

**잠금 없는 SPSC 링 버퍼** (`spsc_ring.cpp`): 생산자 스레드 하나, 소비자 스레드 하나. 생산자는 `tail`만,
소비자는 `head`만 쓰므로 잠금이 필요 없다. 대신 **메모리 순서**가 중요하다:
- 생산자: 칸에 값을 쓴 **뒤에** `tail`을 `release`로 올린다.
- 소비자: `tail`을 `acquire`로 읽은 **뒤에** 칸을 읽는다.
이 짝이 "값이 다 쓰이기 전에 소비자가 그 칸을 읽는 것"을 막는다. 위치는 계속 늘어나는 정수로 두고
`& (용량 - 1)`로 칸을 구한다(용량은 2의 거듭제곱). 꽉 참 = `tail - head == 용량`, 빔 = `tail == head`.
`head`와 `tail`을 다른 캐시 줄에 두려고 `alignas(64)`를 쓴다(같은 줄이면 두 코어가 줄을 서로 빼앗는다).
실행: 500만 개를 넣고 받아 순서 오류 0을 두 번 확인했다(맥 M2). 이 실행은 오류가 없다는 걸 보여 줄 뿐
메모리 순서가 맞다는 증명은 아니다. 약한 메모리 모델 CPU(ARM)에서 `relaxed`로 바꾸면 깨질 수 있는 코드다.

## 틀 (외워 둘 것)

```python
# 크기 고정, count로 꽉 참/빔 구분
push: if count == cap: (덮어쓰기면) head를 한 칸 밀고 그 자리에 쓰기 / (거절이면) 실패
      else: buf[(head + count) % cap] = x; count += 1
pop:  if count == 0: 실패
      x = buf[head]; head = (head + 1) % cap; count -= 1
```

꽉 참과 빔을 구분하는 세 방법: ① 개수를 따로 센다(예제 1) ② 한 칸을 일부러 비워 둔다(`(tail+1)%cap == head`가
꽉 참) ③ 위치를 감싸지 않고 계속 늘리며 차이로 판단한다(예제 2).

## 자주 하는 실수

- **꽉 참과 빔이 둘 다 `head == tail`**: 위 세 방법 중 하나를 꼭 쓴다.
- **`%` 대신 `&`를 쓰는데 크기가 2의 거듭제곱이 아님**: 틀린 칸을 쓴다.
- **덮어쓰기에서 head를 안 밀기**: 가장 오래된 값이 "가장 새것"이 돼 순서가 깨진다.
- **잠금 없는 버전에서 메모리 순서를 relaxed로**: x86에서는 우연히 돌다가 ARM에서 깨진다.
- **SPSC 큐를 생산자 둘이 쓰기**: `tail`을 둘이 같이 올리면 깨진다. 여럿이면 MPSC/MPMC 설계(CAS)나 잠금이 필요하다.
- **용량 0**: 나눗셈·나머지에서 0으로 나누기. 예제는 아무것도 안 하게 막았다.

## 복잡도

넣기·꺼내기 O(1), 메모리 O(용량), 추가 할당 없음.

## 서빙 시스템과의 연결

- **지표 버퍼**: 최근 N초·N개의 지연·토큰 수만 들고 이동 평균·백분위수를 내는 곳 (예제 1). ttalkkak 자동 증감이 들고 다니는 최근 샘플 기록도 같은 역할이다(시간 기준으로 자른다는 점만 다르다).
- **프로세스·스레드 사이 큐**: 서빙 엔진의 API 서버 ↔ 엔진 코어처럼 생산자와 소비자가 나뉜 곳 (예제 2의 발상). 공유 메모리 링 버퍼로 복사를 줄인다.
- **장치 명령 큐**: GPU·NPU 드라이버는 호스트가 명령을 링 버퍼에 쓰고 장치가 읽는 구조를 흔히 쓴다. ROCm의 사용자 공간 큐(AQL)도 링 버퍼에 쓰고 doorbell로 알린다(층별 공부 ⑪).
- **네트워크 카드**: NIC의 송수신 descriptor ring.
