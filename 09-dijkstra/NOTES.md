# 다익스트라 (가중치 있는 최단 경로)

## 한 줄 요약

링크마다 비용(지연)이 다를 때 한 출발점에서 모든 곳까지의 최단 거리를 구한다. **비용이 0 이상**일 때만 맞다.
BFS(02번)는 비용이 모두 같을 때의 특수한 경우다.

## 왜 맞나

힙(04번)에서 지금 거리가 가장 짧은 서버를 꺼내면, 그 거리는 확정이다. 다른 길로 오려면 아직 안 꺼낸
(더 먼) 서버를 거쳐야 하고, 비용이 음수가 아니니 거쳐서 짧아질 수 없기 때문이다. 확정된 서버에서 이웃의
거리를 줄여 보는 것(완화, relax)을 반복한다. 비용이 음수면 이 논리가 깨진다 → 벨만-포드.

## 두 예제

**최단 경로와 경로 복원** (`kv_route`): 서버 S에서 T로 KV 캐시를 보낼 때 지연이 가장 짧은 경로.
거리를 줄일 때마다 "어디서 왔는지"(`prev`)를 적어 두면, T에서 거꾸로 따라가 경로를 얻는다.
예제 입력: 1 → 3 → 6, 지연 11 (직통 링크 1-6은 30이라 더 느리다).

**여러 출발점** (`nearest_replica`): 복제본이 있는 서버 여러 대 중 각 서버에서 가장 가까운 것까지의 지연.
복제본마다 따로 돌리면 R배 느리다. 복제본 전부를 거리 0으로 힙에 넣고 한 번만 돌리면 된다.

둘 다 무작위 그래프 300개로 Floyd-Warshall(모든 쌍 최단 거리) 정답과 비교해 맞는 것을 확인했다.

## 틀 (외워 둘 것)

```python
import heapq
dist = [INF] * (n + 1); dist[s] = 0
heap = [(0, s)]
while heap:
    d, u = heapq.heappop(heap)
    if d > dist[u]: continue          # 낡은 항목 건너뛰기 (필수)
    for v, w in adj[u]:
        if d + w < dist[v]:
            dist[v] = d + w
            prev[v] = u               # 경로가 필요하면
            heapq.heappush(heap, (dist[v], v))
```

```cpp
using Item = std::pair<long long, int>;                     // (거리, 노드) — 거리가 먼저
std::priority_queue<Item, std::vector<Item>, std::greater<>> pq;   // 최소 힙
```

## 자주 하는 실수

- **낡은 항목 확인(`if d > dist[u]: continue`) 빠뜨리기**: 같은 노드가 여러 번 꺼내져 느려진다(최악 시간 초과).
- **C++ 최대 힙 그대로 쓰기**: `greater<>`를 빼면 먼 것부터 꺼내 틀린다. 또는 거리를 음수로 넣는다.
- **튜플 순서**: (거리, 노드) 순이어야 거리로 정렬된다.
- **방향**: 양방향 링크면 두 번 넣는다. 문제가 단방향인지 읽는다.
- **INF와 넘침**: C++에서 `INF + w`가 넘친다. `dist[u]`가 INF면 건너뛰거나 `long long`과 충분히 큰 값.
- **음수 비용에 다익스트라**: 틀린다. 벨만-포드나 SPFA.
- **모든 쌍이 필요한데 N번 다익스트라 vs Floyd**: 노드가 수백 개 이하면 Floyd O(N³)가 간단하다.

## 복잡도

힙 다익스트라 O((N + M) log N). 여러 출발점도 한 번 돌리므로 같다.

## 서빙 시스템과의 연결

- **KV 캐시·텐서 전송 경로**: 서버·스위치 사이 지연이 다를 때 가장 빠른 경로 (예제 1, ⑭ 서버 사이).
- **가장 가까운 복제본으로 보내기**: 여러 출발점 (예제 2). 지역별 엔드포인트 선택, CDN과 같은 발상.
- **토폴로지 인식 배치**: 링(ESL)이나 스위치 구조에서 홉·지연을 따져 이웃한 칩을 고르는 일(운영 층의 device plugin)도 그래프 거리 문제다.
- 실제 라우팅 프로토콜(OSPF 등)도 링크 상태로 최단 경로를 계산한다.
