# 이분 탐색

## 한 줄 요약

"여기까지는 아니고, 여기부터는 맞다"처럼 **한 번 바뀌면 다시 안 바뀌는(단조)** 조건의 경계를, 범위를 반씩
줄이며 O(log n)에 찾는다. 정렬된 배열에서 값 찾기는 그중 한 경우일 뿐이다.

## 두 가지 쓰임: 예제

**경계 찾기** (`slo_ratio`): 정렬된 지연 기록에서 "X ms 이하가 몇 %인가". 조건 `a[i] > X`는 앞쪽은
거짓, 어느 지점부터 계속 참이다. 그 첫 지점(upper bound)이 곧 X 이하의 개수다. 질의가 많아도 정렬 한 번 +
질의당 O(log N).

**답을 이분 탐색** (`pipeline_split`): 레이어 비용을 GPU K장에 연속으로 나눌 때 가장 무거운 GPU의 비용을
최소로(파이프라인 병렬의 단계 나누기). 답을 직접 구하는 건 어렵지만, "가장 무거운 단계를 C 이하로 할 수
있나?"는 앞에서부터 채우는 욕심으로 O(N)에 답할 수 있다. C가 크면 가능, 작으면 불가능이고 그 사이 경계가
답이다. 그래서 C를 이분 탐색한다(전체 O(N log(합))). "최댓값의 최소" / "최솟값의 최대" 문제는 거의 이 틀이다.

## 틀 (외워 둘 것)

"조건이 처음 참이 되는 위치"를 찾는 한 가지 틀만 외운다. 답은 항상 [lo, hi] 안에 있다.

```python
lo, hi = 가능한_최솟값, 가능한_최댓값      # 답이 반드시 이 안에 있게
while lo < hi:
    mid = (lo + hi) // 2
    if ok(mid):        # 참이면 답은 mid이거나 더 왼쪽
        hi = mid
    else:              # 거짓이면 답은 mid 오른쪽
        lo = mid + 1
return lo
```

- 경계 찾기: `ok(i) = a[i] > x` (upper bound) 또는 `a[i] >= x` (lower bound), 범위 `[0, len(a)]`
- 답을 이분 탐색: `ok(C) = C로 가능하냐`, 범위는 문제에서 답이 될 수 있는 최소~최대

라이브러리:

```python
import bisect
bisect.bisect_left(a, x)    # a[i] >= x인 첫 i
bisect.bisect_right(a, x)   # a[i] >  x인 첫 i
```

```cpp
std::lower_bound(a.begin(), a.end(), x) - a.begin();   // >= x 첫 위치
std::upper_bound(a.begin(), a.end(), x) - a.begin();   // >  x 첫 위치
```

## 자주 하는 실수

- **무한 루프**: `lo = mid`로 두면 `lo + 1 == hi`일 때 영원히 안 줄어든다. 위 틀(`hi = mid` / `lo = mid + 1`)을 고정해서 쓴다.
- **범위를 잘못 잡기**: 답이 범위 밖에 있을 수 있으면 틀린다. 예제 2의 `lo = max(cost)`(레이어 하나는 쪼갤 수 없음).
- **조건이 단조가 아님**: 이분 탐색 전에 "C가 커지면 가능이 유지되나?"를 먼저 확인한다.
- **lower/upper 혼동**: "x 이하 개수"는 upper bound, "x 미만 개수"는 lower bound.
- **C++ 넘침**: `(lo + hi) / 2` 대신 `lo + (hi - lo) / 2`. 합계 범위는 `long long`.
- **정렬 안 한 배열에 bisect**: 결과가 조용히 틀린다.
- **욕심 확인 함수의 경계**: `load + c > cap`에서 등호를 넣으면 cap을 꽉 채우지 못해 답이 커진다.

## 복잡도

경계 찾기 O(log n). 답을 이분 탐색은 O(확인 비용 × log(범위)).

## 서빙 시스템과의 연결

- **SLO 비율·백분위수**: 정렬된 지연 기록에서 "X ms 이하 비율", "p99 값"(예제 1).
- **파이프라인 병렬 단계 나누기**: 레이어를 GPU에 연속으로 나눠 가장 느린 단계를 최소로(예제 2). 단계 하나가 느리면 파이프라인 전체가 그 속도로 돈다.
- **SLO를 지키는 최대 부하 찾기**: 동시 요청 수를 늘리면 지연이 늘어나는(단조) 경우, 부하 시험을 이분 탐색으로 줄일 수 있다(guidellm의 sweep와 같은 발상).
- **용량 계획**: "이 처리량을 내려면 복제본이 최소 몇 개?"도 확인 함수가 있으면 이 틀.
