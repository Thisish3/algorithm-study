# 힙 (우선순위 큐)

## 한 줄 요약

"지금 가장 작은(또는 큰) 것"을 계속 꺼내야 할 때 쓴다. 넣기·꺼내기 O(log n), 맨 위 보기 O(1).

## 왜 정렬이 아니라 힙인가

정렬은 데이터가 처음에 다 있을 때 한 번 하면 끝이다. 데이터가 **중간중간 들어오면서** 매번 최솟값이
필요하면, 매번 정렬하는 건 O(n log n)씩 든다. 힙은 들어올 때마다 O(log n)으로 순서를 유지한다.

예제(`sjf_scheduler`)가 그 경우다. 요청이 시간에 따라 도착하고, GPU가 빌 때마다 "도착해 있는 것 중
가장 짧은 것"을 고른다.

**왜 짧은 것부터인가**: 모든 작업이 처음부터 다 와 있다면, 짧은 것부터 하는 순서가 평균 대기를 최소로
만든다. 앞 작업의 처리 시간이 뒤에 기다리는 모든 작업의 대기에 더해지므로, 앞에 짧은 것을 둘수록
더해지는 합이 작다(두 작업의 순서를 바꿔 보면 증명된다).

**주의**: 작업이 시간에 따라 도착하면, "지금 와 있는 것 중 가장 짧은 것"은 규칙일 뿐 항상 최적은 아니다.
예: (도착 0, 10초), (도착 1, 1초). 규칙대로면 0초에 10초짜리를 시작해 평균 (10+10)/2 = 10.
1초까지 기다렸다가 1초짜리부터 하면 (1+12)/2 = 6.5로 더 짧다. 문제가 "이 규칙대로 하라"고 정해 줄 때 쓰는 패턴이다.

## 틀 (외워 둘 것)

```python
import heapq
heap = []
heapq.heappush(heap, (key, value))   # 튜플이면 첫 원소로 비교
key, value = heapq.heappop(heap)     # 가장 작은 것
heap[0]                              # 꺼내지 않고 보기
# 최대 힙: 부호를 뒤집어 넣는다
heapq.heappush(heap, -x); -heapq.heappop(heap)
```

```cpp
priority_queue<int> maxh;                              // 기본은 최대 힙
priority_queue<int, vector<int>, greater<int>> minh;   // 최소 힙
minh.push(x); minh.top(); minh.pop();                   // pop은 값을 돌려주지 않는다
```

시간에 따라 도착하는 작업 패턴:

```text
도착순 정렬 → while (남은 작업 or 힙):
    지금까지 도착한 것을 전부 힙에 넣기
    힙이 비었으면 시각을 다음 도착으로 건너뛰기
    아니면 하나 꺼내서 처리, 시각 증가
```

## 자주 하는 실수

- **파이썬은 최소 힙뿐**: 최대 힙은 부호를 뒤집는다. 꺼낼 때 다시 뒤집는 것을 잊기 쉽다.
- **C++ `priority_queue`는 최대 힙이 기본**: 최소 힙은 `greater<>`.
- **C++ `pop()`은 값을 안 돌려준다**: `top()` 먼저, 그다음 `pop()`.
- **놀고 있는 시간 처리**: 힙이 비었는데 작업이 남았으면 시각을 다음 도착으로 옮겨야 한다. 안 하면 무한 루프.
- **같은 키 비교**: 튜플 두 번째 원소까지 비교한다. 비교 불가능한 객체를 넣으면 에러 → (key, 순번, 객체).
- **중간 원소 삭제**: 힙은 임의 삭제가 느리다. 지울 것을 따로 표시해 두고 꺼낼 때 건너뛴다(lazy deletion).

## 복잡도

작업 n개: 정렬 O(n log n) + 힙 넣기·꺼내기 n번씩 O(n log n).

## 서빙 시스템과의 연결

- 서빙 엔진의 스케줄러가 대기 요청 중 무엇을 먼저 돌릴지 정할 때 우선순위 큐가 쓰인다(우선순위 스케줄링).
- 짧은 작업 먼저(SJF)는 평균 대기를 줄이지만 긴 요청이 계속 밀릴 수 있다(굶주림). 실제 시스템은
  기다린 시간이 길수록 우선순위를 올리는 식으로 보완한다.
- KV 캐시에서 오래 안 쓴 블록부터 지우기(LRU)는 힙이 아니라 해시+연결 리스트가 보통이다(다음 주제).
